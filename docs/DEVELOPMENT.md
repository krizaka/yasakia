# Development

## Commands

| Command | What it does |
| :--- | :--- |
| `npm run setup` | Zero to running: `.env` (generated secrets), PostgreSQL + pgvector on :5435, migrations, seed — idempotent |
| `npm run dev` / `build` / `start` | The API and the web pages on :3000 |
| `npm run check` | lint (ESLint, i18n check + scan, UI ratchet) + type-check + unit tests + docs freshness — before every push |
| `npm run test:e2e` | The feature scenarios over HTTP, on their own database (`yazakia_e2e`) and server (:3100) |
| `npm run db:up` / `db:down` | Start / stop the dev database |
| `npm run db:generate -- --name <what>` | A SQL migration from a schema change (read it before committing) |
| `npm run db:migrate` | Apply pending migrations |
| `npm run db:seed` | The seed accounts (idempotent, refuses `NODE_ENV=production`) |
| `npm run db:status` | Applied vs. pending migrations, row counts |
| `npm run db:reset -- --yes` | Drop the **local** schema, migrate, seed (refuses a non-local URL) |
| `npm run db:studio` / `db:psql` | Drizzle Studio / psql in the dev container |
| `npm run db:dump` / `db:restore -- <file>` | Local backups in `backups/` (git-ignored) |
| `npm run docs:generate [-- --check]` | API and database references, the architecture data, the krizaka.com sync |
| `npm run workspace -- clone\|status\|pull` | The Yazakia repositories side by side (`yazakia.workspace.json`) |
| `npm run mail:templates:preview` | Every e-mail template and language rendered to `apps/web/.mail-preview/` |

Destructive commands are local-only **by construction**: they refuse `NODE_ENV=production`, any `DATABASE_URL` whose
host is not this machine, and they act on the database named in `DATABASE_URL` (a worktree on its own database never
touches the shared `yazakia_db`).

The dev database is the Docker Compose project **`yazakia`** (container `yazakia-postgres-dev`, port 5435): it lives
next to Orochia's (`orochia-postgres-dev`, 5432) and Orazaka's without touching them.

## Schema changes

1. Edit `packages/db/src/schema/*.ts` (the source of truth).
2. `npm run db:generate -- --name <what_changed>` and **read the SQL**.
3. `npm run db:migrate`, then `npm run docs:generate`.
4. Commit schema + migration + regenerated docs together.

Never edit an applied migration: fix forward. Migration `0000_extensions` (hand-written) creates `vector`, `cube` and
`earthdistance`; everything after it is generated by drizzle-kit.

## Tests

- **Unit** (`npm test`, Vitest): sessions and codes, 18+, the position rounding, the photo access rule, encryption at
  rest and key rotation, URL signatures (Bunny token, uploads, local media), image normalisation (metadata stripped),
  storage adapters, mail templates and delivery, rate limits, the realtime door, the database pool (one per process,
  named, small), fail-closed configuration.
- **Realtime contract** (`REALTIME_IT=1 npx vitest run apps/web/lib/realtime.integration.test.ts`, with `DATABASE_URL`
  and optionally `REDIS_URL`): two buses stand for two instances.
- **End-to-end** (`npm run test:e2e`): `e2e/scenarios.mjs` drives the real API with real sessions on PostgreSQL — sign-up
  (18+ server-side), sign-in, tokens and their revocation, profile, rounded position, photos (signed upload, metadata
  stripped, signed view, who may see them), blocks, reports (encrypted; operators behind token + allow-list), push
  tokens, events over LISTEN/NOTIFY, export, suspension, deletion and the purge — and a final scan of every answer: no
  raw media URL, no storage key, no score. Relationships that PY3's endpoints will create (a batch, an intro) are set in
  SQL. A new feature adds its scenarios there.

## Rules a change keeps

- Every rule that decides access lives in `apps/web/lib/` (`access.ts`, `photos.ts`, `account.ts`, …) or a package —
  never inline in a route. Routes: authenticate → validate (zod) → call lib → respond.
- The first sentence of a handler's JSDoc is its summary in `API_CONTRACTS.md`; keep it true.
- No user-facing string outside `apps/web/messages/` (`npm run check:i18n`). No raw palette colour, no `light:`
  (`npm run ratchet`, at zero).
- Media: never a raw URL or a storage key in an answer (the e2e scan fails the suite).
- The pool: `@yazakia/db` only — never `new Pool()` in the app (one pool per process, `docs/DEPLOYMENT.md`).
