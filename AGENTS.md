# Yasakia — Governance Contract (agent-neutral)

> **Single source of truth** for architecture, code and agent-behaviour rules across the **Yasakia** repositories:
> [`krizaka/yasakia`](https://github.com/krizaka/yasakia) (this one — the API, the packages, the docs, the legal pages)
> and [`krizaka/yasakia-mobile`](https://github.com/krizaka/yasakia-mobile) (the iOS and Android app, Expo), which
> carries a short `AGENTS.md` that defers here.
> This file is **agent-neutral**: `CLAUDE.md` (and any other agent file) only **imports** it (`@AGENTS.md`).
> Every generation, review or refactor **must** enforce these rules without exception.
>
> Code-derived references, regenerated by `npm run docs:generate`: [`docs/API_CONTRACTS.md`](docs/API_CONTRACTS.md)
> (every endpoint and its access rule) and [`docs/DATABASE.md`](docs/DATABASE.md) (every table, index, foreign key,
> check, enum — and the design notes). How to work day to day: [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md).

**Yasakia** is the dating app where you talk first: an AI agent gets to know you, then opens a **small batch** (3 to 5)
of profiles that fit **both ways** — and the next batch waits for a **debrief** of the last one. No swipe, no catalogue,
no score shown. The third open-source product of the [`krizaka`](https://github.com/krizaka) organisation, next to
Orazaka (sovereign AI) and Orochia (video for creators).

## 1. Execution & developer experience

- **One command to start**: `npm run setup` (checks Node ≥ 22 and Docker, writes `.env` with a generated
  `AUTH_SESSION_SECRET` and `DATABASE_ENCRYPTION_KEY`, starts PostgreSQL 16 + pgvector on :5435, migrates, seeds). Then `npm run dev`.
- **No shell scripts.** Tooling is Node (`scripts/*.mjs`, no dependencies) behind `npm run`.
- **One `.env` at the repository root**, read by the web app (`next.config.mjs`), drizzle-kit, the migrator and the
  seed (`packages/db/src/load-env.ts`). Real environment variables always win; CI and production ship no file.
- The dev database is its own Docker Compose project (**`yasakia`**, container `yasakia-postgres-dev`, port **5435**):
  it never touches Orochia's (5432) or Orazaka's databases.

| Command | What it does |
| :--- | :--- |
| `npm run setup` | Zero to running: env, database, migrations, seed (idempotent) |
| `npm run dev` / `build` / `start` | The API and the web pages on :3000 |
| `npm run check` | lint (ESLint, `krizaka-i18n check` + `scan`, `krizaka-ratchet`) + type-check + unit tests + docs freshness — before every push |
| `npm run test:e2e` | The feature scenarios over HTTP on their own database (`yasakia_e2e`) and server (:3100) |
| `npm run db:up` / `db:down` | Start / stop PostgreSQL |
| `npm run db:generate -- --name <what>` | SQL migration from a schema change (read it before committing) |
| `npm run db:migrate` / `db:seed` / `db:status` | Apply migrations / the seed accounts (refuses production) / applied vs. pending, row counts |
| `npm run db:reset -- --yes` | Drop the **local** schema of your branch's database, migrate, seed (refuses a non-local URL, the shared `yasakia_db` and `*_demo`; dumps first) |
| `npm run db:studio` / `db:psql` / `db:dump` / `db:restore -- <file>` | Studio, psql, local backups |
| `npm run docs:generate [-- --check]` | API + database references, architecture data, the krizaka.com sync |
| `npm run workspace -- clone\|status\|pull` | The two repositories, side by side |
| `npm run mail:templates:preview` | Every e-mail template and language rendered to `apps/web/.mail-preview/` |

- Destructive commands are **local-only by construction**: they refuse `NODE_ENV=production` and any `DATABASE_URL`
  whose host is not this machine, and act on **the database named in `DATABASE_URL`**.
- **One database per branch (org rule).** A session or a worktree works on its own database, named from its branch
  (`yasakia_<branch>`, `scripts/lib.mjs` `databaseForBranch`; `npm run setup` on a branch writes it into `.env` and
  creates it) — never on the shared `yasakia_db`. `db:reset` and `db:restore` **refuse** `yasakia_db` and every
  `*_demo` database (only `demo:seed` writes `*_demo`) and **dump the target to `backups/` before any destruction**
  (`destructionRefusal`, tested in `scripts/db-guard.test.mjs`).

**Dependency rules**

- `apps/web` → `packages/*`. Packages never import the app; `packages/db` depends on no other package.
- Route handlers stay thin: authenticate (`requireUser` / `requireAdmin`) → validate (zod) → call `lib/` → respond.
  **Every rule that decides access lives in `lib/access.ts` or the domain module** — never inline in a route.
- **The database pool is `@yasakia/db`'s, and only it**: one pool per process on `globalThis`, `DATABASE_MAX_CONNECTIONS`
  (default 5), named connections (`yasakia-web`, `yasakia-listen`, `yasakia-migrate`), `DATABASE_DIRECT_URL` (optional)
  for LISTEN and migrations. Never `new Pool()` in the app. The budget is in [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).
- **Shared UI and platform bricks come from npm, never from a copy** (`@krizaka/*`). A missing generic piece is built
  in krizaka-ui first, released, then adopted. No product word (`yasakia`) goes into a platform brick.
- The AI is consumed **over HTTP, through Orazaka only** (`packages/ai`, the service key `AI_ENGINE_API_KEY`) — never a model
  provider, never as a library. The engine's address and key are read at the edge (`lib/env.ts` `aiProvider`, the route) and handed to the domain.

## 3. Absolute invariants

### A. Never a score, never a fake person
- No similarity, score or rank number ever reaches a client: reasons are **words**, both ways (the e2e checks every
  answer, the agent's included; the foundations' e2e already scans every answer for `score` / `similarity` keys).
- No fake profile and no invented figure in the real database. The development seed says it is one (`@seed.yasakia.test`,
  "(seed)", generated geometric avatars — never a real photo). The demo (a fictional cast) lives only in `yasakia_demo`.

### B. Private photos, zero-trust media
- **No raw media URL and no storage key ever reaches a client.** `GET /api/photos/{id}` evaluates access
  (`photoAccess`, `lib/access.ts`) and only then signs a URL for that viewer, **300 seconds**, at an allowed width (the
  Bunny Optimizer resizes; the width is inside the signature). The e2e suite scans every answer.
- Who sees a photo: its owner; anyone else only when it is APPROVED, its owner is not suspended, **no block in either
  direction**, and the viewer has the owner in a current batch (OPEN / DEBRIEF_DUE, not withdrawn) or shares an OPEN /
  CONTINUED intro. Otherwise 404.
- Uploads: declared type (JPEG, PNG, WebP) and size (≤ 10 MB, `packages/media/src/limits.ts`), a URL signed for one
  photo and 300 s, the bytes checked against the declaration, then **re-encoded** at completion — orientation applied,
  **every metadata block stripped (GPS included)**, ≤ 2048 px, blurhash computed — then `PhotoModeration.review()`
  (V1: approved automatically; a report reopens the review). Six photos at most.

### C. Position, minimisation
- The position is **rounded to ~1 km before it is written** (`lib/geo.ts`); `geo_precision_m` is stored; the exact
  coordinates exist nowhere. Never the phone's contacts.

### D. Safety in the product
- **18+**: the date of birth is checked **by the server** when an account is created (`lib/age.ts`); under 18 the code
  is spent and no account exists. The date is never shown (only the owner's export carries it).
- **Block**: immediate, invisible, mutual in effect — in the same transaction the intro closes (`BLOCKED`) and each is
  withdrawn from the other's current batch (`applyBlockEffects`).
- **Report**: normalised reasons (UNDERAGE and THREAT first), persisted **before** the acknowledgement, details
  **sealed**; a report in an intro freezes it; the reported person is never told. Operators read reports through
  `/api/admin/*` only: `OPERATOR_API_TOKEN` **and** `OPERATOR_ALLOWED_IPS` (empty in production = nobody).
- **Delete my account, in the app**: `DELETE /api/me` deletes everything at once (one transaction, cascades), the media
  are purged from storage right after and retried until done (≤ 30 days by policy), a confirmation e-mail leaves;
  `account_deletions` keeps nothing personal. **Export**: `GET /api/me/export` (JSON, background past 1 s, sealed, 24 h).

### E. Encryption at rest
- Sensitive facets, report details and stored exports are sealed with AES-256-GCM (`packages/db/src/crypto.ts`), bound
  to their row and column (AAD), with `DATABASE_ENCRYPTION_KEY` — **mandatory in production: the server refuses to start
  without it**. The `facets` table is written and read through `packages/db/src/facets.ts` only. Rotation:
  `DATABASE_ENCRYPTION_KEYS_PREVIOUS`. No data is ever used to train a model.

### F. Fail-closed configuration and sessions
- **Environment variables are named by bounded context** (krizaka/.github#46): `<CONTEXT>_<THING>` with CONTEXT one of
  `APP_` `DATABASE_` `AUTH_` `MEDIA_` `MAIL_` `PUSH_` `PAYMENTS_` `REALTIME_` `ABUSE_` `OBSERVABILITY_` `AI_` `OPERATOR_` —
  never the product (`YASAKIA_…`) nor a vendor (`BUNNY_…`, `MAILGUN_…`): a vendor is a value (`MEDIA_STORAGE_PROVIDER=bunny`,
  `MAIL_PROVIDER=mailgun`). `NEXT_PUBLIC_` only where the browser needs it. Every variable is declared once in
  `apps/web/lib/env-vars.ts` (zod: context, need, secret, schema, what it does); `env.test.ts` refuses an undeclared or
  misnamed one, `assertProductionConfig` checks every value set, `docs/DEPLOYMENT.md` *Configuration* is generated.
- Secrets are read through `apps/web/lib/env.ts`: mandatory in production (503 + logged name when missing),
  development defaults otherwise; `assertProductionConfig` (instrumentation.ts) refuses to **start** a production server
  without the session secret, the encryption key, the database, the Bunny storage and Mailgun.
- **Sessions**: sign-in = sign-up (while `AUTH_SIGNUP_ENABLED=true`; §6.2 for the web console's cookie sessions), by a 6-digit e-mail code (keyed hash, 10 minutes, 5 attempts, used once, 5 codes an
  hour per address); `POST /api/auth/verify` with `client: "native"` answers a stateless signed token (`yz1.…`, 30 days)
  sent as `Authorization: Bearer` — **no cookie, no password** for the app (the web console has its own cookie sessions and operator-provisioned passwords, §6.2). Authorisation is not in the token: `requireUser`
  re-reads the account on every request (suspension 403, deletion 401, `session_version` for "sign out everywhere").
- No AI engine configured → the AI endpoints answer 503 (`AI_UNAVAILABLE`), never a demo mode, never a stand-in. The scenarios
  (`npm run test:e2e`, CI) talk to `e2e/orazaka-stub.mjs`, which speaks Orazaka's contract without a model; the real engine is
  proven by the live run on dev (`scripts/dev-journey.mjs`).
- E-mail: production always delivers through Mailgun and **refuses** without it — a sign-in code is never logged there.

### G. E-mails are templates
- Every e-mail is `sendTemplate(id, { to, locale, vars })` (`lib/mail.ts`) over `apps/web/mail-templates/<id>/<locale>/`
  (`subject.txt`, `body.html`, `body.txt`) in the shared `_layout`; the registry `MAIL_TEMPLATES` declares each id and
  its variables. English and French; French is a language of design, not a translation.

## 4. Data, migrations and seed

- The **Drizzle schema** (`packages/db/src/schema`) is the source of truth; `docs/DATABASE.md` is generated from it.
- Change workflow: edit the schema → `npm run db:generate -- --name <what_changed>` → **read the SQL** →
  `npm run db:migrate` → `npm run docs:generate` → commit schema + migration + docs together.
- **Never edit or delete an applied migration**; fix forward. `0000_extensions` is hand-written (extensions);
  everything after is generated.
- Production applies migrations with the bundled migrator (`packages/db/dist/migrate.cjs`) as the DigitalOcean
  `PRE_DEPLOY` job, through `DATABASE_DIRECT_URL` when set.
- The seed is development data, idempotent (by e-mail), and refuses `NODE_ENV=production`.

## 5. API conventions

- One `route.ts` per path. Path ids validated as UUIDs (invalid → **404**, never 500); bodies parsed with **zod**
  (`.strict()` where a field must not sneak in); answers `{ success: true, … }`; errors through `handle` /
  `errorResponse` (no internals leaked; configuration → 503; database unavailable → 503 + `Retry-After`).
- Refusals a client acts on carry a stable `code` (`refuse(status, code, message)`): the app words them, never parses
  the English message.
- Ownership is enforced **in the query** (`where id = … and account_id = me`): another account's id is a 404.
- Abusable mutations are rate-limited **per subject and per IP** (`limitAction`, `lib/rate-limit.ts`), 429 with
  `code: RATE_LIMITED` and `Retry-After`. The IP is `clientIp()` (`lib/client-ip.ts`), read from the right of
  `X-Forwarded-For` or `ABUSE_CLIENT_IP_HEADER`. `ABUSE_RATE_LIMIT_STORE=postgres` before a second instance.
- **Realtime goes through `lib/realtime.ts` only**, which knows typed events only (`batch.ready`, `intro.opened`,
  `intro.message`) — payloads are ids, never documents. Transport `@krizaka/realtime`: `REALTIME_BUS=postgres`
  (default; NOTIFY channel `yasakia_events`) or `redis` (prefix `yasakia:rt:`) — keep the names: two versions share
  them during a deploy. `GET /api/events` is the account's SSE stream.
- Push through `lib/push.ts` → `@krizaka/push` (Expo Push), only in production or with `PUSH_DELIVERY=on`.
- Background loops start in `instrumentation.ts` (`lib/jobs.ts`) and share work with `FOR UPDATE SKIP LOCKED`.
- The **first sentence of the JSDoc** above each handler is the endpoint's summary in `docs/API_CONTRACTS.md`; the
  access column is read from what the handler calls (`requireUser`, `requireAdmin`, a signature). Keep both truthful.

## 6. The web pages

- The API's web app (`apps/web`) has the three public pages — `/privacy`, `/terms`, `/delete-account` — and the signed-in console (§6.2), in English and French
  (`/en/…`, `/fr/…`; `proxy.ts` sends an address without a language to the reader's: cookie, then `Accept-Language`).
  Anything else is a 404 (the owl). Errors: the falcon (`components/errors/PageState`, Orochia's pattern).
- Built with `@krizaka/ui` (`PageHero`, `Page`, `Mascot`, `ThemeToggle`, `YasakiaLogo`), `@krizaka/tailwind` and the
  brand `@krizaka/tokens/brands/yasakia.css` (emerald → turquoise). Both themes through the role utilities; **no raw
  palette colour, no `light:`, no `[var(--…)]`, no `className` template** — the ratchet (`lint-ratchet.json`) is at zero
  and stays there.
- **Every user-facing string lives in `apps/web/messages/{en,fr}.json`** (`errors/` for the error pages, kept small for
  the client) — `krizaka-i18n check` + `scan` in `npm run lint`. Never choose a text with a locale ternary.
- The legal texts and `docs/PRIVACY.md` describe the same code: change them together.

### 6.1 The public dev site — `apps/site` (dev.yasakia.com)

- A **static export** (`output: "export"`, built with `assetPrefix: "/site-assets"`) — three pages: landing, how it works, demo —, English
  at the root, French under `/fr`. It is **served by the web service** (one DigitalOcean deployment, §6.2): `scripts/sync-site.mjs`
  copies `apps/site/out` into the git-ignored `apps/web/public` (pages and root files at their paths, chunks under `/site-assets`)
  and `apps/web/next.config.mjs` maps each address to its file (`LANDING_PAGES`, trailing slash kept: `skipTrailingSlashRedirect`).
  URLs, canonical, sitemap, robots, llms.txt and JSON-LD are unchanged. Built from the same bricks (`@krizaka/ui` `LandingPage`,
  `HowItWorksPage`, `PageHero`), strings in `apps/site/messages/{en,fr}.json`, the same lint rules and ratchet.
- **It never offers what does not exist**: no sign-up, no download, store button or waiting list (sign-up is closed by
  `AUTH_SIGNUP_ENABLED=false`; the people who test sign in under `/app`), no invented profile or figure. Media come from the CDN only
  (`apps/site/lib/media.ts`, hashed; the web app's CSP allows that one host).
- The footer shows « A Krizaka product » (→ krizaka.com) and the build's version, `APP_VERSION` = `package.json` version + short
  commit (`APP_COMMIT_SHA`, passed at build).
- `npm run build` builds the site, syncs it and builds the web app; `npm run dev:site` serves the site alone on :3002.

### 6.2 The signed-in console — `apps/web` (dev.yasakia.com/app · admin.yasakia.com)

- **What it is**: the person's space and the administration console, one Next.js app, **two hosts**: `app.yasakia.com` (the
  person) and `admin.yasakia.com` (the administration — `APP_ADMIN_HOST`, `lib/host.ts`, `proxy.ts`: on the admin host only the
  administration exists, on any other host it is a 404, so the console costs nothing more). Its own DigitalOcean app
  (`deploy/digitalocean/web.app.yaml`, project `yasakia`), which also serves the public landing (§6.1): an app that holds a *static
  site* component stalls on deploy once it is a trusted source of the shared cluster, so the landing is files served by the service.
  URLs: the landing at `/`, `/fr`, `/how-it-works`, `/demo`; the legal pages at `/{en|fr}/{privacy|terms|delete-account}`; the
  console under **`/app/{en|fr}/…`** (`app/app/[locale]/(app)`): 
  `sign-in`, the home (`/`), `account`, and the administration — `admin` (overview), `admin/users` (+ detail), `admin/reports`
  (moderation), `admin/intros`, `admin/audit`, `admin/health` (health + version) — under AppShell, a DEV badge, never indexed.
  Built **only** from our bricks:
  `@krizaka/ui` (`AuthLayout`, `AppShell` — the console template —, `DashboardLayout`, `SettingsLayout`, `DetailLayout`,
  `DataTable` in server mode, `form`, `Dialog`, `ConfirmButton`, `Timeline`), `@krizaka/query` (server state, the live
  stream), `@krizaka/i18n` (the client receives only its `console` slice), the brand `yasakia`.
- **Sessions**: a browser session is an opaque random token in an HttpOnly, SameSite=Lax cookie (`yasakia_session`,
  Secure in production, scoped to the app path), kept only as its SHA-256 in `web_sessions` — one row per device, listed
  and revocable on the account page. `requireUser` accepts the app's bearer token **or** the cookie (a cookie write must
  come from this origin: `assertSameOrigin`). Password sign-in (`POST /api/auth/password`, scrypt hashes in
  `account_credentials`) is for the console; the app keeps signing in by e-mail code. Passwords are provisioned by an
  operator (`npm run db:qa-accounts`: the `qa+user@` / `qa+admin@` accounts, passwords from the environment, never printed).
- **Sign-up is closed server-side**: `AUTH_SIGNUP_ENABLED` is false unless it says `true`. The e-mail-code flow then signs
  existing accounts in and creates none (`SIGNUP_CLOSED`, 403; a stranger gets no e-mail and the same answer). e2e runs a
  second server with it closed.
- **Administration**: `accounts.role = ADMIN` **and** an address in `AUTH_ALLOWED_IPS` (empty in production = nobody) **and**
  a session. A failed lock is a 404 on pages (the console does not announce itself) and a 403 on `/api/admin/*`, which also
  answers the operator token. Operators see state, role and counts — never a date of birth, a message, a photo or a score.
  Suspend (with a reason) ends every session at once; restore lifts it; an administrator cannot be suspended from the console.
  Every sign-in (and refusal), password change, suspension, restoration and deletion is in `audit_log` (append-only; ids and
  a few words; deleting an account blanks its address from the lines it acted in).
- **A dev deployment** (`NEXT_PUBLIC_APP_ENV=dev`) may run with `MAIL_PROVIDER=none` and `MEDIA_STORAGE_PROVIDER=none`: those
  routes answer 503 — nothing is faked, and production still refuses to start without Mailgun and Bunny.
- Every string is a message (`console.*`); tables take their words from `console.admin.table`; errors are worded by the
  server's stable `code`, never by its English.

## 7. Testing

- **No test, not done.** Every feature and every fix ships with its tests in the same pull request: a unit test for
  logic, a scenario in `e2e/scenarios.mjs` for a route or a flow, a render test for a component's states.
- **A fix starts with a failing test** that reproduces the bug; the fix turns it green and the test stays as the guard.
- **CI runs them all on every pull request and must be green** before merge. A test is never skipped, weakened or
  deleted to get there.
- **Unit** (`npm test`, Vitest): pure logic — tokens and codes, 18+, rounding, the photo access rule, crypto and
  rotation, signatures, image normalisation, storage, mail, rate limits, the realtime door, the pool, configuration.
- **Realtime contract** (`REALTIME_IT=1`, CI with PostgreSQL + Valkey): two buses stand for two instances.
- **End-to-end** (`npm run test:e2e`): `e2e/scenarios.mjs` drives the real API with real sessions on PostgreSQL +
  pgvector. A new feature adds its scenarios there; the final scan (no raw media URL, no storage key, no score) stays.

## 9. Security

- No credentials in code or in git; `.env` is git-ignored. Report vulnerabilities privately ([SECURITY.md](SECURITY.md)).
- Security headers on every answer (HSTS, CSP `default-src 'self'`, frame denial, nosniff, referrer and permissions
  policies, COOP) in `next.config.mjs`.
- Constant-time comparisons for every signature and token; signed URLs expire in 300 s.

## Static rules & codemods (ast-grep)

The org code rules (addendum 2026-10-15) are lint rules, not review comments. [`@ast-grep/cli`](https://ast-grep.github.io)
is a **pinned devDependency** (no global install, CI reproduces local): `sgconfig.yml` + `rules/*.yml` (one rule per file,
with a message and, where safe, a `fix:`; written for Tsx and `.ts` is parsed as Tsx too, so each rule covers `.ts` and `.tsx`), `rule-tests/` (valid/invalid cases of each rule).

| Rule | What it refuses |
| :--- | :--- |
| `no-hand-ms-*`, `no-get-time-difference`, `no-get-time-arithmetic` | hand-written time arithmetic (`n * 60 * 1000`, `a.getTime() - b.getTime()`): date-fns, or a duration read from the settings |
| `no-env-in-domain` | an `env` import in domain code (`packages/*/src`, `src/`): the value arrives as a parameter |
| `no-db-in-service-or-rules` | a db client / schema import in `*.service.ts`, `*-service.ts`, `*.rules.ts`, `*-rules.ts` |
| `no-ts-enum` | the TypeScript `enum` keyword (`as const` object + derived type, or a Postgres enum) |
| `no-enum-string-compare` | `x.status === "OPEN"` (field named status/kind/role/reason/state/direction compared to a string literal) |
| `no-ambient-clock` | `new Date()` / `Date.now()` in domain code: the clock is injected |
| `no-types-at-package-root` | `types.ts` at a package root (`<feature>/<feature>.types.ts`) |
| `no-unjustified-numeric-export` | a numeric (or `…ToMilliseconds(n)`) `export const` in feature code without `// @fixed: <reason>` just above |

- **Run**: `npm run lint` runs everything (it includes `ast-grep test` and the ratchet). `npx ast-grep scan` lists the
  violations with their message; `npm run lint:sg:test` runs the rule tests.
- **Ratchet**: `scripts/sg-ratchet.mjs` counts the violations per rule and refuses any increase against
  `sg-ratchet.json` (same idea as `krizaka-ratchet` / `lint-ratchet.json`: the debt only goes down). Fixed some? Lock the gain with
  `npm run sg:ratchet:update` (it never raises a count and records a new rule at its current count). A new rule is
  added with its test in `rule-tests/` and its baseline in the same pull request. The script is identical in every
  Krizaka TypeScript repository (keep the copies identical; its unit test is `scripts/sg-ratchet.test.mjs`).
- **Codemods**: `npm run sg:fix` applies the `fix:` of the rules (`ast-grep scan --update-all`) and adds the date-fns import;
  behaviour is identical — run `npm run lint && npm test` after, and land the result in a small pull request.
- A rule is never silenced to get a PR green; fix the code, or (a business parameter that is a technical fact) justify it with `// @fixed:`.

## 10. Definition of done

1. `npm run check` passes and `npm run build` succeeds.
2. Schema changes ship with their migration and regenerated `DATABASE.md`.
3. New behaviour has scenarios in `e2e/scenarios.mjs`, and `npm run test:e2e` passes.
4. The invariants of §3 still hold; no credential, demo shortcut, fake profile or score reaches production code.
5. Web page changes are checked at phone and desktop widths, in both themes and both languages.
6. The change ships with its tests (§7) — a fix with the test that failed before it.

## 11. Agent session protocol

- Read this contract and `docs/DEVELOPMENT.md` before changing code; `npm run workspace -- status` when the change spans
  repositories.
- Prefer the domain modules (`lib/*`, `packages/*`) over logic in routes.
- Never weaken an invariant to make a test pass; never commit secrets, dumps or `.env`.
- PR captures (screenshots, recordings, metrics) are never committed: they go to Bunny Storage under
  `pr-assets/<repo>/<pr-or-topic>/` with [`scripts/pr-assets.mjs`](https://github.com/krizaka/krizaka-com/blob/main/scripts/pr-assets.mjs)
  of krizaka-com, and the PR body links their CDN URLs.
- Branches `feat/…`, `fix/…`, `chore/…`; Conventional Commits; never push to `main` (protected: PR + CI, squash only).
